# HSR 星穹铁道配置方法

## HSR 专项是什么

星穹铁道有两款常用的第三方脚本，各有所长：

- **三月七小助手（M7A）**：体力副本和周常跑得好。
- **StarRailAssistant（SRA）**：日常奖励领取、差分宇宙跑得好。

HSR 专项的意义就在这儿：**你不用二选一**。在一个托管里同时接入两款脚本，哪个任务交给哪个，由你决定。AUTO-MAS 负责启动游戏、按顺序调用脚本、失败了重跑，以及记住周常这周做没做过。

**能跑的内容**（具体以你装的脚本版本为准）：

- 体力副本：拟造花萼（金）、拟造花萼（赤）、侵蚀隧洞、饰品提取
- 历战余响（每周重置）
- 日常与奖励：兑换码、邮件、委托、勋礼、每日实训等
- 周常：差分宇宙、货币战争

## 准备工作

开始前先完成以下准备，可以避开大部分常见问题。

1. **装好你要用的脚本**（M7A 和 SRA 至少装一个，两个都装才能混用）。
2. **每个脚本都手动打开一次。** 脚本第一次启动才会生成自己的配置文件（三月七是 `config.yaml`，SRA 是 `%APPDATA%\SRA\configs` 下的档案），AUTO-MAS 要读它才能显示「MAS 管控任务」右边那一堆配置项；原生配置更是缺了它就过不了任务开始前的检查。SRA 那边如果打开后没生成，在里面随便保存一次设置即可。
3. **装好星穹铁道 PC 端**，国服官方客户端。
4. 从官方渠道下载脚本。遇到安全软件拦截时，先核对来源与拦截详情；确认误报后只为可信安装目录设置排除项。
5. **路径别用中文和空格**，例如 `D:\M7A`、`D:\SRA`。中文路径历来容易引发图像识别和路径解析问题。

::: warning 路径要选文件夹，不是选 exe
保存时 AUTO-MAS 会检查你选的文件夹里有没有对应的 exe，选错会直接弹窗拦下来：

| 填这个 | 文件夹里得有 |
| --- | --- |
| 三月七路径 | `March7th Assistant.exe` |
| SRA 路径 | `SRA-cli.exe` |
| 游戏路径 | `StarRail.exe` |
:::

## 创建 HSR 托管

### 1. 新建托管

进入 **托管管理** → **新建托管** → 选择 **HSR脚本** → 确定。软件会跳到托管配置页。

### 2. 托管与游戏配置

| 配置项 | 填什么 |
|---|---|
| **托管名称** | 随便起个你认得出的名字，比如「主号星穹」 |
| **三月七路径** | M7A 所在**文件夹** |
| **SRA 路径** | SRA 所在**文件夹** |
| **SRA 配置档案** | SRA 可以存多份配置档案，这里选用哪一份。默认「自动」，见下 |
| **MAS 管理游戏** | 由 AUTO-MAS 负责启动游戏、切脚本时重启、以及盯着游戏进程。默认「是」，游戏已经在跑时会自动跳过启动，不用为此关掉它。**建议只在「原生配置 + 云游戏」时选「否」**；关掉后上面三件事一起失效 |
| **游戏路径** | 星穹铁道所在**文件夹**。「MAS 管理游戏」选「是」时必填 |
| **游戏最大启动等待时间** | 启动游戏后等待客户端可操作的秒数，默认 60 秒，可按机器性能调大 |
| **运行时设为 1920×1080 窗口模式** | 打开后任务开始前临时改写注册表把游戏设成 1920×1080 窗口模式，任务结束后还原。脚本的图像识别按这个分辨率调校，画面比例不对时打开它 |
| **兑换码仅在变化时执行** | 默认打开。兑换码没变就跳过这一步，避免每天白跑一遍 |

::: tip 只装了一个脚本也能用
M7A 和 SRA 填一个就行，另一个留空。留空的那个不会出现在账号页的执行引擎选项里。
:::

::: tip 关于 SRA 配置档案
SRA 把设置保存成 `%APPDATA%\SRA\configs` 下的多份档案。选哪一份决定两件事：MAS 管控任务的配置项显示的是哪份内容、原生配置按哪份运行。

留「自动」的话优先用 `Default`，没有就用文件名排序的第一份——这也是以前唯一的行为。如果你选的档案后来被删了或改了名，AUTO-MAS 会退回自动模式并在托管页和账号页都给出提示，不会闷声换掉。
:::

::: warning 改分辨率要在游戏关着的时候
「运行时设为 1920×1080 窗口模式」是通过改注册表生效的，游戏已经在运行时改不动。AUTO-MAS 会在日志里提示你关掉游戏后重新执行，本轮仍会照常跑，只是分辨率没改成。
:::

### 3. 设置重试和超时

这几项决定任务的超时与重试行为，默认值适用于大多数情况，可按机器性能调整。

| 配置项 | 说明 | 默认值 |
|---|---|---|
| **失败任务最大尝试次数** | 一个任务**总共**尝试几次，含第一次。默认 3 ＝ 首轮 + 最多 2 次补跑 | 3 |
| **日常任务超时限制（分钟）** | 日常 / 体力 / 奖励类任务最多跑多久 | 20 |
| **周常任务超时限制（分钟）** | 差分宇宙 / 货币战争最多跑多久 | 60 |
| **启用低性能兼容模式** | 只影响 M7A 跑差分宇宙。M7A 差分跑得不稳就打开 | 关闭 |

::: tip 任务分配不在这一页
「哪个任务交给哪个脚本」现在是**每个账号各自决定**的，在账号页设置，不在托管页。同一个托管下的两个账号可以一个用 SRA、一个用 M7A。
:::

### 4. 外部脚本更新

托管页的 **外部脚本更新** 管理已填写路径的 M7A / SRA：

- 默认在运行前检查更新；选 **不更新** 后只手动更新。旧版「运行后」设置会按「运行前」执行。
- 三月七默认从 GitHub 下载，可改 Mirror 酱；SRA 默认从 AUTO-MAS 下载站下载，也可按页面选其他来源。
- 使用 Mirror 酱时，在这里填写 HSR 的 CDK，不会自动使用 MAS 自身更新设置的 CDK。
- 两款脚本可分别 **检查更新** 或 **立即更新**。先核对目标版本与更新结果，再开始任务。

## 创建 HSR 账号

在 **托管管理** 表格里点 **添加账号**，然后填基本信息：

| 字段 | 填什么 |
|---|---|
| **账号名称** | 显示名称。跑货币战争时会作为「开拓者名称」写给脚本 |
| **启用** | 关掉的账号会被跳过 |
| **账号** | 手机号等登录账号，只在需要 SRA 自动切号时才要填 |
| **密码** | 登录密码，同上 |
| **服务器** | 目前只有官服 |
| **剩余天数** | 还能代理几天。`-1` 是不限制；**每天最多减一次**，而且要当天日常阶段至少有一个模块成功才减；减到 0 就跳过这个账号。原生配置的账号不递减，但一样会在 0 时被跳过 |
| **备注** | 随便写 |

::: warning 关于账号密码
账号密码保存在本地并自动加密，不会上传。

**托管页填了 SRA 路径、且这个账号是「MAS 管控」模式时，这两栏才会出现。** 但真正会拿去登录 / 切号，还要看你确实把某个开启的模块交给了 SRA；没有的话填了也用不上。

另外，别把你的 `data/` 目录或托管配置 JSON 发给别人，里面有加密后的凭据。
:::

## 运行模式：MAS 管控还是原生配置

每个账号都要选一个 **运行模式**，这决定了「谁说了算」：

| 模式 | 谁决定跑什么 | 适合谁 |
|---|---|---|
| **MAS 管控**（默认） | AUTO-MAS。任务开关、执行引擎、副本、各项配置都在这个页面上设 | 想在一个界面里管完所有号 |
| **原生配置** | M7A / SRA 自己。AUTO-MAS 只负责按时把它拉起来 | 已经在脚本里配得很顺手，只想要个定时器 |

### 原生配置

原生配置**不需要在 AUTO-MAS 里做任何配置**。你在 M7A / SRA 自己的界面里怎么设的，跑的就是什么，改完立刻生效，不用回来同步一次。

用法就两步：选好运行模式，把要跑的脚本开关打开。

::: warning 原生配置会忽略这个页面上的其它设置
任务开关、账号密码、体力副本、MAS 管控任务里的配置项，在原生配置模式下**一个都不会生效**——那些是 MAS 管控模式才用的。下面的「进度与重置」区也只在 MAS 管控模式下出现。

另外原生配置没有失败补跑（脚本自己怎么跑就怎么算），单次运行上限固定 2 小时，而且只能走自动代理，不支持在调度中心单独运行某个账号。
:::

## 配置体力副本

**体力配置** 区有四个下拉框，对应四类副本。不想刷的留空就行：

| 下拉框 | 刷的是 |
|---|---|
| **拟造花萼（金）** | 角色经验 / 光锥经验 / 信用点 |
| **拟造花萼（赤）** | 行迹材料 |
| **侵蚀隧洞** | 遗器 |
| **饰品提取** | 位面饰品 |

金和赤的选择互不影响，可以同时存着。

下面还有几项：

- **刷取副本**：从上面四类里挑本次实际要刷的那一类。
- **当前生效关卡**：显示你选中的关卡，只是给你确认用的。
- **历战余响**：从脚本读出来的关卡里挑一个，不刷就留空。
- **历战余响开始日**：设成周几，到了那天本周还没刷就去刷。刷完这周就不再重复。

::: tip 副本选项跟着执行引擎走
这些副本选项不是 AUTO-MAS 自己编的，而是**从你的 M7A / SRA 里读出来的**——体力交给谁，就读谁的配置。两边的副本列表不一样，所以**每个引擎各存一份你选的关卡**，换引擎后要重新选一次，换回去原来的选择还在。
:::

## MAS 管控任务

这是 MAS 管控模式的主区域，左边是四个任务模块，右边是选中模块的详细配置。

| 模块 | 包含什么 | 开关默认 |
|---|---|---|
| **体力与培养目标** | 开拓力刷副本、历战余响 | 开 |
| **日常与奖励** | 兑换码、邮件、委托、勋礼、每日实训等 | 开 |
| **差分宇宙** | 差分宇宙 | 关 |
| **货币战争** | 货币战争 | 关 |

差分宇宙和货币战争可分别启用，但共用周常完成记录；本轮开始时若周常未完成，两项可一起排入队列，其中任一完成后本周后续运行都会跳过周常。

每个模块可以单独指定 **执行引擎**（SRA 或三月七助手）。只填了一个脚本路径时就只有那一个可选。

### 详细配置是从哪来的

右边那一堆配置项**不是 AUTO-MAS 自己定义的**，而是实时从你的 SRA / 三月七助手配置文件里读出来的，读的就是脚本此刻保存的值。你在这里改动某一项，AUTO-MAS 只记下**你改过的那几项**（叫「覆盖值」），其余仍跟着脚本走。

所以有几个直接的后果：

- 脚本升级后多了新选项，这里会自动出现，不用等 AUTO-MAS 更新。
- **切换执行引擎等于换一整套配置项**，两个引擎的字段名根本不一样。当前引擎下改过的值不会带过去，但会保留着，切回来还在。
- 有些东西 AUTO-MAS 故意不接管，比如 SRA 的兑换码列表，那些只能在脚本自己的界面里填。

::: warning 有两类设置会被 AUTO-MAS 强制关掉
托管模式下，AUTO-MAS 会在临时配置里强制关掉脚本自己的**通知推送**和**任务完成后动作**（三月七的 `after_finish`、SRA 的 `missionAccomplished`）。

原因是这些动作会把游戏甚至整台电脑关掉——三月七只要 `after_finish` 不是「无操作」，收尾时就会先把游戏关掉，本阶段剩下的模块只能中止并进入补跑；设成「关机」时还会在 60 秒后真的关机。通知则由 AUTO-MAS 自己统一发。

这只影响托管模式下 AUTO-MAS 跑的那一轮，你在脚本里的原设置跑完会还原。**原生配置不改这两项**，你设了什么就是什么；唯一的例外是 SRA 的 Windows 弹窗通知——只要填了 SRA 路径，整轮运行期间都会被临时关掉，跑完还原。
:::

### 重置为源配置

模块列表右上角的 **重置为源配置** 会**删掉这个账号在 MAS 里改过的全部覆盖值**（所有模块、所有字段），之后各项都按脚本当前配置显示和运行。源配置文件本身不会被改动。

这个操作不可撤销，点了会先弹确认。

### 「N 项失效覆盖」是什么意思

脚本升级、换了 SRA 配置档案之后，你之前改过的某个字段可能已经不存在了，或者类型对不上。这时该项会标成失效：

- **运行时直接忽略它，按源配置执行**，不会因此报错或中断任务。
- 详情面板里会列出是哪几项、为什么失效、你当初存的是什么值。
- 点 **清除无效覆盖** 可以把它们从这个账号的配置里删掉。同样只动 AUTO-MAS 这边，不碰源配置文件。

## 周常进度不用你操心

这类任务 AUTO-MAS 会自己记账：

- **历战余响**：单独按周记录。
- **差分宇宙、货币战争**：这两个**共用同一条「周常」记录**。本轮开始时周常未完成，两项都启用就会一起排入本轮队列；任意一个被日志确认完成后，整条周常记录记为完成，本周后续运行会跳过两项。

按国服周一 04:00 重置（等价于 UTC+4 的周一 00:00），不是本机周一零点。

### 手动改进度

账号页底部的 **进度与重置** 区（只在 MAS 管控模式下出现）可以看到历战余响和周常各自「本周做没做过」，每项都能手动 **标记完成** 或 **重置**。

两种情况用得上：你已经自己进游戏做完了，标记一下让 AUTO-MAS 别再跑；或者你想强制重跑一次，点重置。

::: tip 这几个按钮只改记录
它们只改 AUTO-MAS 自己的记账，**不会真的去驱动脚本执行任务**。
:::

## 运行与日志

配好之后，把托管加进 [调度队列](/docs/task-scheduler) 就能自动跑了。三件事值得知道：

- **游戏可能被反复重启**：三种情况会重启——同一账号的任务在两个脚本之间切换、同一账号从日常阶段进入周常阶段（与用哪个脚本无关）、以及每轮补跑之前。都是故意的，为了防止脚本状态互相干扰。三者都只在「MAS 管理游戏」为「是」时才发生。
- **你的 M7A / SRA 配置不会被弄坏**：AUTO-MAS 跑之前先备份，跑完自动还原。
- **可重试的失败会自动补跑**：按「失败任务最大尝试次数」重试，游戏管理开启时会先重启游戏。配置错误，以及云游戏登录超时、排队超时或时长不足等无法靠重试解决的问题，不会反复补跑。

### 出问题要交哪些日志

- `debug/app.log` —— AUTO-MAS 主程序日志
- `debug/frontend.log` —— 界面日志

如果看起来是某个脚本本身的问题，再附上 M7A / SRA 自己的日志（位置见各脚本文档）。

::: tip 发日志前先看一眼
AUTO-MAS 会把 M7A / SRA 的输出原样转进自己的日志，所以里面可能有你的游戏 UID（脚本做 OCR 时会读到）。账号密码是脱敏过的，UID 不是。发到公开 issue 前建议先搜一下自己的 UID 打码。

另外 M7A 的日志级别设成 DEBUG 时，转进来的量会非常大（一次运行上千行很正常）。想让日志清爽点，把 M7A 自己的 `log_level` 调回 `INFO`。
:::

## 常见问题

### 新建托管时没有 HSR 这个选项

你的 AUTO-MAS 版本太老，还没有 HSR 专项，去 [下载页](/download/auto-mas) 更新。更新后重启一次软件。

### 路径怎么填都提示不对

**你可能选到了 exe 本身。这里要选的是文件夹。** 确认文件夹里直接放着对应的 exe：三月七是 `March7th Assistant.exe`、SRA 是 `SRA-cli.exe`、游戏是 `StarRail.exe`。也别选到子目录里去。

### 副本列表是空的

副本选项读的是脚本安装包里自带的清单（三月七 `assets\config\instance_names.json`，SRA `tasks\config	railblaze_power.toml`），解压就有，**跟你有没有打开过脚本无关**。所以基本只有两个原因：**路径没填到脚本根目录**（最常见，里面得能看到上面那两个目录），或者**刚换过体力的执行引擎**——两边副本列表不一样，换了要重选，页面上会有提示。

### 任务状态不对，该跑的没跑 / 跑过了又跑

- 先看账号页的任务开关是不是你想的那样。
- 周常按周重置，跨周会自动清零。
- 在 **进度与重置** 区手动标记或重置，可以立刻纠正状态。
- 还是不对就看 `debug/app.log`，里面有脚本退出情况的记录。

### M7A 跑差分宇宙不太稳

打开托管页的 **启用低性能兼容模式**。另外球队、赐福、演算策略这些 AUTO-MAS 管不到，得你提前在 M7A 里配好。

### SRA 跑完货币战争没积分

先在游戏内确认积分和奖励领取情况，再查看所用 SRA 版本的任务说明与日志。MAS 的完成记录不等于所有游戏奖励都已领取；领取行为由上游脚本决定。

### 游戏被反复重启

三个来源：脚本之间切换、日常阶段跑完进周常、以及补跑之前。都是故意的，防止脚本状态互相干扰。

把任务都交给同一个脚本能少掉第一种，但只要开了差分宇宙或货币战争，日常跑完那次重启躲不掉。完全不想让 AUTO-MAS 碰游戏，就把托管页的「MAS 管理游戏」关掉——代价是启动、切换和进程监测都得你自己管。

### 任务失败了，但日志里没有脚本的输出

先看 `debug/app.log` 中启动脚本时的具体错误，核对安装目录、可执行文件和脚本依赖。没有输出本身不能确定原因；若安全软件有拦截记录，再核对下载来源并按误报处理。
