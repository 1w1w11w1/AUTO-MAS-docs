# M9A 配置方法

::: tip 提示
M9A 现在是 [MFW 脚本](/docs/script-guide/maafw) 的一种：选中 M9A 的目录，AUTO-MAS 会自动认出它并按 M9A 处理。脚本页、用户页、更新、内嵌副本都和其它 MFW 项目一样，本页只讲 M9A 特有的部分。
:::

## 什么是 M9A？

M9A 是一个《1999》（亿韭韭韭）第三方软件，能够轻松完成1999日常代理、自动深眠、活动刷取等重复性工作。

基于 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 图像识别技术强力驱动。

## 安装 M9A

1. 前往 <Pill name="M9A 仓库" :image="{ light: '/icons/github.svg', dark: '/icons/github-dark.svg', }" link="https://github.com/MAA1999/M9A/releases/latest"/> 或 <Pill name="Mirror 酱" image="https://mirrorchyan.com/favicon.ico" link="https://mirrorchyan.com/zh/projects?rid=M9A&scouce=AUTO-MAS-Web"/> 下载 **Windows 发行包**（`M9A-win-x86_64-vX.Y.Z-MFAA.zip` 或 `-MXU.zip` 都可以）。
2. 解压至任意文件夹（比如 `D:\M9A`），解压完的目录里应该直接就能看到 `interface.json`。

::: warning 注意
**不需要**先手动打开 M9A 一次，也不用装 .NET 运行时——AUTO-MAS 不启动 M9A 自己的界面，MaaFramework 运行时和 Agent 的 Python 环境由 AUTO-MAS 自己准备。
:::

## 配置脚本

1. 进入 **脚本管理**，单击 **新建脚本**，选择 **MFW脚本**（选 **M9A脚本** 也一样，两者只差一个默认名字）。
2. 在 **项目目录** 处单击 **选择本地目录**，选中解压出来的 M9A 目录。AUTO-MAS 会把它导入成自己的副本，认出这是 M9A，脚本类型自动变成 **M9A**。
3. **游戏资源** 选服务器（官服 / B 服 / 国际服…），在 **模拟器管理** 里选好模拟器和实例。
4. 其它项——运行配置、项目更新（GitHub / Mirror 酱、运行前 / 运行后自动更新）——见 [MFW 项目配置方法](/docs/script-guide/maafw)。

::: tip 服务器是脚本级的
M9A 的 `interface.json` 把服务器声明成"资源"，所以在 AUTO-MAS 里服务器选在**脚本**上，一个脚本下的所有用户都是同一个服。官服和 B 服都要跑就建两个脚本，指向同一个目录即可（各有一份副本，互不影响）。
:::

## 配置用户

1. 在 **脚本管理** 的脚本表格内单击 **添加用户**。
2. 填用户名和备注。**账号** 一栏只有官服会用到（见下面自动切换账号），其它服只是备注。
3. 可以添加多个用户，AUTO-MAS 按用户列表顺序依次执行每个用户的任务队列。

### 任务队列

任务列表就是 M9A `interface.json` 里声明的任务，以你手上这一版 M9A 为准。选中加入队列、拖动排序；M9A 自带的 **预设模板**（比如"日常"）点一下批量加入。每个任务的 **任务配置** 就是 M9A 界面上的那些选项，默认值与 M9A 一致。

**启动游戏、关闭游戏不用自己加。** 运行时 AUTO-MAS 会自动补齐首尾：

```text
启动游戏 → [切换账号] → 你排的任务 → 关闭游戏
```

队列里已经有的不会重复加；你自己排了别的位置也不动。

### 自动切换账号

**只有官服支持**，其它服受 M9A 限制做不到。

脚本的游戏资源是官服、用户的 **账号** 填了值时，AUTO-MAS 在启动游戏之后自动插入一个 **切换账号** 任务并把账号填进去；不需要切号就留空。资源不是官服时账号只作备注，不会插入切换。

### 每日 / 每月只做一次

脚本页 **运行配置** 里的 **每日完成后跳过** / **每月完成后跳过** 就是原来 M9A 脚本上的"每日心相只做一次""每月深眠只做一次"：把 **每日心相（意志解析）** 加进每日、**自动深眠**、**自动醒梦** 加进每月，当天 / 当月成功过一次之后自动跳过。也可以按需加别的任务。

## 从旧版 M9A 脚本升级过来

老版本 AUTO-MAS 里的 **M9A 脚本** 是一套单独的适配，升级后第一次启动时自动迁移成上面这套，你不需要重建：

- 脚本、用户、模拟器、通知设置、代理次数记录都原样保留，每个用户的任务队列换成新格式，任务选项按名字对上。
- 旧的"服务器"是用户级的，新的是脚本级的：脚本取启用用户里最多人用的那个服务器；服务器不一样的用户会被**停用**并在备注里写明原因，你把它挪到另一个脚本（或改脚本的资源）后再启用。
- "队列结束后自动更新"变成 **项目更新 → 运行后**，没开的变成 **不更新**；更新源这样定：M9A 目录里原来配了 Mirror 酱 CDK 就用它，否则用 AUTO-MAS 更新设置里的 CDK，都没有就用 GitHub。
- 旧的"运行时间限制"是日志停滞阈值，新的是整轮硬超时，统一改成 120 分钟。
- 迁移前的配置备份为 `config/ScriptConfig.json.m9a-legacy-<时间戳>.bak`，保留最近三份；迁移结果启动后会弹一条通知列出来。
- 原来在 M9A 目录里跑出来的配置备份（`data/<脚本 ID>/M9ABackups/`）保留在原地，不再出现在配置恢复里。

::: warning 迁移后第一次运行
会从原来的 M9A 目录导入一次副本（十几秒到一分钟），之后就在副本上跑，原目录不再被改动，想删也可以删。
:::

## 常见问题

### 我选的是通用 MFW 脚本，怎么变成 M9A 了？

类型由项目决定：目录里的 `interface.json` 是 M9A 的（Mirror 酱 rid 为 `M9A` 或 GitHub 指向 `MAA1999/M9A`），脚本就会被认成 M9A，自动补启动 / 关闭游戏和切号。反过来，M9A 脚本换成别的项目目录会变回通用 MFW。用户和设置都保留。

### 任务失败了怎么查？

先看模拟器连上了没 → 再看运行页日志（每个任务的开始 / 成功 / 失败、最后停在哪个节点都有）→ 失败时会自动截图，在历史记录里能看到 → 还不清楚就去 `history/<日期>/<用户名>/` 翻这一轮的 `.maafw.log`。

### 代理次数怎么不涨？

**次数是按 UTC+4 时区算日期的**，和你电脑的日期可能差几小时，跨日时间点不是本地 0 点。当天次数已经达到 **用户单日代理次数上限** 的话，后面的用户会被直接跳过。

### 支持范围

| | 状态 |
|---|---|
| 官服 | 支持，且是唯一能自动切号的服 |
| B服 / 其它服 | 支持，但不能自动切号（M9A 的限制） |
| MFAAvalonia 包 / MXU 包 | 都支持（AUTO-MAS 不启动界面，只用 `interface.json`） |
| MuMu 模拟器 / 雷电模拟器 | 支持 |
| 其它模拟器 | 没测过，可能有问题 |
