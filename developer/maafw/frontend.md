# 前端与交互

## 要点

- 脚本页与用户页都是 MFW 的公共页面，风味只经注册表差异化（见 [风味](./flavor.md)）。
- 用户页任务队列的**左右两栏框架不动**（等高定高、各自滚动、左窄右宽）；两栏**内部**（队列条目、右栏的选项编辑器）可以按需改。新区块放插入点，不进两栏。
- 界面只保留用户必须知道、否则会做错或会丢东西的提示：不复述控件状态，不对选不了的东西告警，不把外部注释原样搬上来。
- 导入后目录字段锁定、只展示副本路径；「复用已导入的项目」入口只在新建对话框。
- 项目显示名：label（与 name 不同才算写了）→ title 第一段去掉版本号 → name，前后端同一口径。

## 脚本页

| 设计 | 为什么 |
| --- | --- |
| 新建时走引导：第 0 步要求运行环境准备好才能往下；最后一步主按钮「创建第一个用户！」，并可从外壳配置导入用户（[#993][993]、[#997][997]） | 环境没准备好，后面配了也跑不起来 |
| 基础信息区左侧是 interface 概览表（表头：项目名 · 版本 · 简介），右侧是「运行环境」面板；「准备运行环境」按钮放在面板标题右侧，不走缓存，失败时同一颗按钮当「重试」（[#843][843]） | — |
| **结论就是日志最后一行，整行一个强调色**，文案就是后端那句结论；不另加状态词、不加进度条、不另弹提示；深色模式下不用成块底色，日志框只留边框 | 一个地方看结论 |
| 导入后目录字段显示副本路径、按钮锁定；内嵌相关的信息只在运行环境日志开头几行体现（来源、导入时版本、当前版本与共用脚本数） | 导入后来源只是记录，不让用户误以为改目录就能换项目 |
| 开发者模式：状态行显示「开发者模式」或「源码形态」标签与同步时间，旁边是「立即同步」；源码形态时开关锁在开着（[#1294][1294]） | — |
| Win32 控制方式两行排完：启动方式 \| 游戏 exe；Unity 分辨率 \| 启动参数 \| 等待时间（秒）\| 键位映射 | — |
| ADB 控制方式：截图 / 输入策略表只留两行，放在包名右侧；Emulator 2.0 选中具体设备后按设备类型显示能力 | — |
| 游戏包名：首次读到 interface 只补空的；切换资源一律覆盖；推不出或有多个候选时不动（[#855][855]） | 不同服的包名不同 |
| 项目更新区：「Mirror 酱 CDK ｜ 代理地址」一行，**输入框下不留说明行**，解释都放进问号；CDK 的问号本身可以点，直达 Mirror 酱；只在「选了 Mirror 酱却没填 CDK」时出一行警告（[#943][943]） | 版面整洁 |
| 填了 CDK 时，输入框下一行小字显示剩余天数与到期日（剩 7 天以内变警告色），CDK 有问题（过期、无效、当日次数用尽等）时显示原因；没填、项目没接入 Mirror 酱、查询失败都不显示。页面打开、预填 CDK 后、输入框失焦且值有变化时各查一次，与所选下载源无关（[#1330][1330]） | 更新检查不带 CDK，CDK 填错原本要等到真正下载时才暴露；这是用户必须知道的信息，查不到时不显示比显示失败更安静 |
| 模拟器与实例下拉只用后端列表自带的「未选择」（值 `-`），前端不再另加「不指定」；列表还没到时显示占位文字（[#1331][1331]） | 同一个值出现两次；与其他专项编辑页一致 |
| `Emulator.Id` 为 `-` 表示未选择，设备下拉与配置查询把它当成空值，不拿它去查模拟器配置（[#1345][1345]） | `-` 是哨兵，不是 id |
| 单任务时限、按任务覆盖与原地打转检测开关都在「按任务设置时限」弹窗里，打转开关在第一行（[#1180][1180]、[#1223][1223]） | — |
| 键位映射：只读框显示「默认 / 已改 N 项」，「设置」打开弹窗；interface 里没有对当前控制器生效的 hotkey 选项时不显示（[#1174][1174]） | — |

## 用户页

| 设计 | 为什么 |
| --- | --- |
| 任务队列两栏等高定高（640 px）、各自内部滚动、左窄右宽（9 / 15）；窗口窄于 992 px 时折成上下两块、每栏 420 px（[#855][855]、[#1037][1037]） | 整体版面整洁 |
| 队列行只留任务名；入口与分组放到右栏副标题；任务说明加「说明」小标题 | — |
| 基础信息里「启用」用下拉；预设不在基础信息里切换（用户信息与队列分开）；从未运行过显示「上次：未运行」 | — |
| 用户页没有「读取 interface」按钮 | 编辑用户时 interface 不会变 |
| 没导入项目时不额外加引导按钮 | 没导入项目时本来就不能正常使用，提示在脚本页 |
| 全局选项在队列上方显示一次（[#1294][1294]） | 每个用户一份 |
| interface 里已没有的任务留成虚影：删除线 +「interface内已无该任务」，只能删；选中后右栏列出原来的设置（密码打码）；「添加任务」里没见过的新任务标 ✦ NEW（[#1147][1147]） | 项目改名后不静默丢配置 |
| 右键菜单：复制任务（插在正下方，选项与显示名一起复制）、修改显示名（最长 40 字）、删除（需确认）；虚影只给删除；受管、不可选、当前不可用的任务不能复制；右键同时选中该行（[#1301][1301]） | — |
| 显示文字相同的行有两份以上时显示「名字 #序号」，序号按队列顺序、只在显示时计算；分组依据就是显示出来的文字 | 用户看到什么就按什么区分 |
| 受管任务与不可选任务被挡在「添加任务」与预设之外；已在队列里的照常显示，并在队列上方给一句提示 | 见 [风味](./flavor.md) |
| 「模板」弹窗分「我的模板 / 项目预设」；「配置导入」弹窗分「本脚本其他用户 / 外壳」（[#1260][1260]） | — |
| 密码类输入是密码框，只看得到「已设置」；checkbox 的最少 / 最多数量有界面限制（[#973][973]） | PI 协议要求 |
| 热键与 setting 分区不进两栏 | 热键是脚本级的，放在脚本页 |

| 设计 | 为什么 |
| --- | --- |
| 选了 MFW / M9A / MSS 后多一步「项目从哪来」：第一行「选择本地目录」，下面直接列出已导入的项目，按项目名 + 版本并成一行，只列与所选类型相同的项目 | 复用是新建阶段的决定；导入后的目录字段只是展示，不在那里放切换 |

## 项目显示名

取名口径：label（与 name 不同才算写了）→ title 按 `|` / `｜` 取第一段并去掉末尾版本号 → name（[#993][993]）。脚本名仍是默认名、为空或是上次自动起的项目名时才自动改成项目名，用户自己起的名字不动。前端 `utils/maafwProjectName.ts` 与后端 `interface/preview.py` 的 `interface_display_name` 保持同一口径，改一边就要改另一边。

为什么：interface 模型在没写 label 时会把 label 补成 name，只看 label 会显示仓库名；title 常常是窗口标题，带版本号与标语，整条显示太长。

## 提示文案原则

| 原则 | 说明 |
| --- | --- |
| 只留用户必须知道的提示 | 真实失败、读取失败、会被忽略的设置 |
| 不复述控件状态 | 不写「配置会保存」「切回即恢复」「由 X 执行」 |
| 不对界面上选不了的东西告警 | 不可选的项本就不该可选，回落不是异常 |
| 外部脚本的原生说明要清洗 | 去掉 true / false、可选值清单、与标题重复的句子；拿不准就不挂问号 |
| 问号只放带行为边界的说明 | 项目目录要包含 interface.json、留空的含义、更新时机与来源、CDK；单位直接写进标签，如「等待时间（秒）」 |
| 面向用户的叫法 | 一律叫「MFW」，指框架本身写「MaaFramework」；「副本」可以用；视图、组、登记、载荷、投影、克隆是内部词，不出现在界面上 |
| 日志只往详细里加 | 可以加分段用时、进度、原因；不做清理——不把英文排障日志改中文、不合并重复行、不删行 |

## 国际化

- 词表 zh-CN、en-US、ja-JP 三份都要加；新文案不硬编码。
- 后端日志与通知不做国际化，中英混杂可以接受。
- 尚未支持按界面语言选择项目自己的语言文件。
